## 推荐方案（私有独立目录）

* 路径：`/Users/michael/Documents/Code/Trae/Tarot-backend`

* 形式：独立私有 GitHub 仓库 + 独立 Vercel 项目

* 原因：安全与治理隔离、符合“前端公开/后端私有”的产品与技术文档要求、避免公开仓库内出现后端源码。

* 本地实施方式：在新的工作区中进行全部后端开发与部署（不在当前前端仓库内操作）。

## 实施步骤（按此执行）

1. 初始化后端项目

* 在 `Tarot-backend` 中初始化 Node/Vercel 项目结构

* 创建两个 Serverless 路由：`api/ai/gemini/generate` 与 `api/ai/zhipu/generate`

* 公共工具：`utils/cors.ts`（`ALLOWED_ORIGINS` 白名单）、`utils/http.ts`（超时、重试、错误处理）

1. 配置与推送

* Git 初始化，创建 `dev` 分支

* 推送到 GitHub 私有仓库（你拥有权限）

1. Vercel 后端项目

* 新建项目（推荐名 `tarot-backend`）并关联私有仓库

* 配置后端环境变量：

  * `GEMINI_API_KEY`、`ZHIPU_API_KEY`（敏感，来自 `.env.local`）

  * `AI_PROXY_TIMEOUT_MS=15000`

  * `ALLOWED_ORIGINS=https://tarot.vercel.app`（或你的前端正式域名）

1. 前端项目

* 在 `tarot` 项目中设置环境变量：

  * `VITE_AI_DEV_PROXY=0`

  * `VITE_AI_BASE_URL=https://<后端域名>`

  * Hedge 相关：`VITE_AI_HEDGE_ENABLED=1`、`VITE_AI_HEDGE_DELAY_MS=0`、`VITE_AI_ABORT_LOSER=1`、`VITE_AI_TIMEOUT_MS=15000`

1. 联调与验证

* 用 curl 验证后端两个路由 200 响应与 CORS 头

* 前端生产环境触发解读流程，观察 Hedge 并发竞速：无 VPN 时 Zhipu通常更快；总超时回退稳定

* 输出部署验收报告，待你确认后合并 `dev -> main`

## 备选方案A（同仓双项目 Monorepo）

* 做法：在当前前端仓库中新建子目录 `server/`，作为后端子项目；在 Vercel 创建一个项目指向 `server/` 子目录。

* 风险：后端源码随前端公开仓库暴露（虽然密钥仍仅在 Vercel 端），不符合你“后端私有”的既定策略，因此不建议。

## 备选方案B（本地临时联调）

* 做法：先在本地启动后端 dev server 供前端联调，生产仍使用私有独立仓库与 Vercel 项目。

* 适用：你希望先验证接口与并发逻辑，再进行远端部署。
